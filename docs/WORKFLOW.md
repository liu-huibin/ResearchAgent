# 多智能体、引用与流式处理

本文说明 ResearchMate 的使用流程、多智能体路由、公开推理说明、引用定位和 SSE 持久化语义。项目概览请先阅读根目录 [README](../README.md)。

## 使用流程

1. 打开前端，新建会话。
2. 如需分析单篇论文，在中间区域上传 PDF/DOCX；它会绑定到当前会话。
3. 如需跨论文检索，在左侧“知识库”上传文件。知识库文件会建立 Chroma 和 BM25 索引；重复 MD5 会被拒绝。
4. 在右侧提问。首次提问会把占位标题“新会话”替换为最多 12 个字符的稳定短标题。
5. 展开“推理与协作说明”可查看各阶段公开报告、工具状态和失败信息。
6. 点击回答或 Agent 公开报告中的蓝色“来源”按钮，阅读器会打开对应文档并高亮引用片段。

会话文档与知识库文档用途不同：

| 类型 | 范围 | 是否建立长期索引 | 用途 |
| --- | --- | --- | --- |
| 会话文档 | 当前会话 | 否 | 当前论文精读、直接问答和可定位引用 |
| 知识库文档 | 全局单用户 | 是 | 跨文档语义/BM25 检索和长期复用 |

## 多智能体工作流

| Agent | 职责 |
| --- | --- |
| `Supervisor` | 判断任务类型、选择流程并汇总最终回答 |
| `ReaderAgent` | 阅读当前文档或检索证据，形成事实基线 |
| `IdeationAgent` | 基于证据提出可验证的科研思路 |
| `ReviewerAgent` | 检查事实一致性、创新性、可行性和可证伪性 |

当前路由：

```text
普通阅读/证据问答：Supervisor → Reader → Finalizer
明确审查/核验任务：Supervisor → Reader → Reviewer → Finalizer
思路/创新/方案任务：Supervisor → Reader → Ideation → Reviewer
                                      └─ 需要修改 → Revision（最多一次）
                                                     → Finalizer
```

每个 Agent 可在最终输出中生成结构化公开报告。系统只将公开报告和确定性的阶段说明发送到前端；中间模型隐藏推理、Prompt 和工具原始载荷不会通过 SSE 或消息历史暴露。

## 引用定位规则

后端使用以下机器标记维持文档与分块映射：

```text
[citation:doc_23:chunk_60]
```

前端将其渲染为蓝色“来源”按钮。点击后调用引用定位接口，校验原文件 MD5，重新匹配原始 PDF 页或 DOCX 段落，并只在唯一匹配时高亮。

以下是普通模型文本，不包含完整定位信息，不能可靠跳转：

```text
[1, Sec.2.3]
[来源 3]
[Fig.2]
```

新工作流会要求 Agent 保留机器标记，并在模型误删标记时补充“可定位来源”。历史回答若只保存了章节号或自拟序号，无法唯一反推出 `document_id/chunk_index`，需要重新提问生成新的可定位引用。

## SSE 与持久化语义

`POST /api/sessions/{session_id}/messages` 返回 `text/event-stream`：

| 事件 | 说明 |
| --- | --- |
| `start` | 本次工作流 `trace_id` |
| `agent` | Agent/阶段开始及公开阶段说明 |
| `report` | Agent 明确生成的结构化公开报告 |
| `action` | 工具调用开始，只包含工具名和状态 |
| `observation` | 工具成功/失败状态，不包含原始载荷 |
| `token` | 最终回答增量 |
| `metrics` | Token、耗时、迭代和工具统计 |
| `error` | 用户可见错误 |
| `done` | 终态确认；`persisted=true` 才表示回答已持久化 |

静默阶段每 5 秒发送 SSE keepalive，并周期性保存运行中检查点。浏览器断开、生成器取消、模型异常或数据库提交失败时，后端会尝试完成状态收尾；重新读取历史时还会把超过超时宽限期的 `running` 记录标记为 `interrupted`，不会自动重放用户问题。
